# DNSGuard v1.1.0 全局默认 DENY 隔离验收

- 被测试提交：`bdc7fb348e052529dec6880e0be94394b6c28ff3`
- 测试环境：独立 Docker Bridge；1 台 Primary、2 台 Secondary、1 台模拟上游
- BIND：`9.20.30`
- 生产 DNS、生产 TSIG、生产配置：未使用

## 默认策略验收

执行：

```bash
./tests/bind-cluster/global-deny-acceptance/run-acceptance.sh --keep
```

测试使用 `qname-wait-recurse no` 的隔离递归配置，根级规则为：

```dns
$ORIGIN global-deny.rpz.local.
* IN CNAME .
```

结果：

| 项目 | 结果 | 证据 |
|---|---|---|
| 全局 deny Zone 加载 | PASS | `named-checkzone` 通过；三台 BIND 均加载 Zone |
| Primary / Secondary SOA | PASS | `1 / 1 / 1` |
| 白名单及多级子域名 | PASS | `allow.example.com`、`deep.sub.allow.example.com` 在三台节点放行 |
| A 重定向 | PASS | `redirect.example.com` 及子域名返回 `192.0.2.250` |
| 多级未知域名 A | PASS | `.com`、`.net`、`.xyz` 随机三级名称返回 `NXDOMAIN` |
| 多级未知域名 AAAA | PASS | 同组随机名称返回 `NXDOMAIN` |
| 多级未知域名 TXT | PASS | 同组随机名称返回 `NXDOMAIN` |
| 根级通配 `.com` | PASS | 三台节点返回 `NXDOMAIN` |
| 被拒绝 QNAME 到达模拟上游 | PASS（本配置） | 未观察到同名查询进入受控上游 stdout |
| 生产 BIND 操作 | NOT RUN | 明确禁止，未连接生产 |

默认验收脚本退出码为 `0`。运行时日志、临时 TSIG 和容器数据留在被 `.gitignore`
忽略的 `tests/bind-cluster/global-deny-acceptance/runtime/`，没有提交到仓库。

## DNSSEC DO=1 复核

执行：

```bash
TEST_DNSSEC=1 ./tests/bind-cluster/global-deny-acceptance/run-acceptance.sh --keep
```

实际结果：客户端收到 `NXDOMAIN`，但在该隔离 BIND 配置中，模拟上游观察到完整的
DO=1 查询名称，因此该项为 **FAIL（上游未阻断）**。这是已记录的 BIND 递归行为限制，
不是 DNSGuard 可以通过控制面自动修复的功能；不能把客户端 `NXDOMAIN` 宣传成查询
未外传。生产管理员必须针对目标 BIND 版本独立评估 DNSSEC、`qname-wait-recurse`、
递归缓存和上游链路。本项目不自动修改这些配置。

## 结论

根级 `* IN CNAME .` 在本隔离配置下能够实现广泛默认拒绝，白名单和 A 重定向优先级
保持有效，且不需要 IANA TLD 列表。该结果不等于所有生产 BIND 配置、查询类型和
DNSSEC 场景均可阻断 DNS 数据外传。v1.1.0 以“控制面只读核对、BIND 管理员独立准备
和维护全局 deny Zone”为安全边界。
