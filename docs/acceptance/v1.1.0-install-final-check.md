## 实际命令

```bash
./install.sh
./tests/docker-initialization-wizard.sh
TEST_DNSSEC=0 ./tests/bind-cluster/global-deny-acceptance/run-acceptance.sh
(cd server && go test ./... -count=1)
(cd server && go test -race ./... -count=1)
(cd server && go vet ./...)
npm run build
bash -n install.sh scripts/install.sh scripts/docker-init.sh
shellcheck -x install.sh scripts/install.sh scripts/docker-init.sh
docker compose --env-file deploy/docker/dnsguard.env.example -f compose.yaml config
git diff --check
```

上述回归命令均退出码 0。上传测试使用临时 Docker Compose 项目和 Chromium/Selenium，不使用生产凭据；导入流程只创建 `draft`，未自动发布。

## 结论

- `./install.sh` 已在隔离环境真实跑通。
- 重复执行安全，不覆盖已有配置、密钥、Token 和数据。
- DENY 基线不会把不存在的测试域名误判为成功。
- 未发现阻止 PR #3 合并的问题。
- DO=1 可能发生 QNAME 上游外传的既有风险保持不变；本验收不宣称完全阻断 DNS 隧道。

**建议合并 PR #3；本报告中的 NOT RUN 项不应被解释为生产环境发布验收。**
