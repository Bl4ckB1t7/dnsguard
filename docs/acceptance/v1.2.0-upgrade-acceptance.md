## 2. 升级前准备

旧版隔离数据包含：

- 已初始化管理员及可用登录凭据；
- 1 条已发布白名单规则；
- 1 条 draft 规则；
- 1 条版本历史；
- 审计记录；
- 3 个 BIND 节点配置及状态；
- `legacy` 策略模式，`RPZ_GLOBAL_DENY_SETUP_DEFERRED=true`。

执行的备份命令：

```bash
tar -czf pre-upgrade-backup.tgz \
  -C <isolated-lab>/pre-upgrade-snapshot \
  data secrets tls bind-logs dnsguard.env test.env
tar -tzf pre-upgrade-backup.tgz
```

备份清单包含 JSON 状态、认证数据、Bootstrap Token、TSIG、TLS 文件和日志目录。报告不包含密钥、Token 或私钥内容。

## 3. 实际升级命令

```bash
git fetch origin main
git archive v1.1.1 | tar -x -C <isolated-lab>/v1.1.1
git archive origin/main | tar -x -C <isolated-lab>/main92
docker compose --env-file .env \
  -f compose.yaml -f compose.bind-network.yaml build --pull=false
docker compose --env-file .env \
  -f compose.yaml -f compose.bind-network.yaml up -d
curl -ksSf https://127.0.0.1:<isolated-port>/api/health
```

容器仅为 `dnsguard-api` 和 `dnsguard-web`；API 通过可选外部 BIND 网络访问隔离节点，Web 未加入外部 BIND 网络。

测试夹具最初手工生成的 env 缺少 `TRUST_PROXY_TLS`、`LISTEN_ADDR` 和 runtime `rpz` 目录；按仓库现有示例补齐后继续测试。该修正仅作用于隔离夹具，不是对生产配置的修改。

## 5. 失败与恢复

### API 启动失败注入

在独立复制的数据目录中将 initialization JSON 替换为无效 JSON：

```text
初始化状态文件损坏: invalid character ...
```

结果：

- API 以非零状态退出；
- 没有覆盖正常升级目录；
- 用升级前快照恢复该复制目录后，API health 最终恢复为 healthy。

结论：PASS。

### 升级过程 API 中断

```bash
docker compose ... stop dnsguard-api
docker compose ... start dnsguard-api
curl -ksSf https://127.0.0.1:<isolated-port>/api/health
```

结果：API 恢复 healthy，legacy/deferred 状态保持。结论：PASS。

### 回滚到 v1.1.1

使用升级前快照恢复到独立 rollback 目录，使用 v1.1.1 Tag 构建的镜像启动：

- health：PASS；
- 管理员登录：PASS；
- legacy 初始化状态：PASS；
- 版本历史、已发布规则和 draft：PASS；
- TSIG 文件校验值保持：PASS。

结论：使用升级前快照回滚可行。

## 8. 已知限制

- DNSGuard 不修改、reload 或 restart 生产 BIND。
- 客户端收到 NXDOMAIN 不等于完整 QNAME 未到达上游。
- 既有隔离测试显示部分 DNSSEC `DO=1` 查询仍可能触发完整 QNAME 上游查询；本轮未将其改写为 PASS。
- 本报告的 BIND、网络、TSIG 和升级结果仅适用于隔离环境。
- GitHub 当前未返回 workflow runs/status checks，不能将其写成 CI PASS；正式发布前应由维护者确认仓库是否需要配置必需 CI。
