## 实际命令

### 公网低频基线

```bash
dig +time=3 +tries=1 22fbd7071c.like.cobaltstrike.cn. A +noall +comments
dig +time=3 +tries=1 +short 22fbd7071c.like.cobaltstrike.cn. A
```

实际结果：`NOERROR`，`10.10.10.10`。

### 隔离 BIND 验收

```bash
STAGED_FIRST_DEPLOYMENT=1 \
./tests/bind-cluster/global-deny-acceptance/run-acceptance.sh --keep
```

结果：退出码 `0`。随后在 Primary、Secondary-1、Secondary-2 容器内执行：

```bash
dig @127.0.0.1 22fbd7071c.like.cobaltstrike.cn. A +tcp +noall +comments
dig @127.0.0.1 22fbd7071c.like.cobaltstrike.cn. A +tcp +dnssec +noall +comments
```

## 关键原始结果（脱敏）

DO=0：

```text
Primary      status: NXDOMAIN
Secondary-1  status: NXDOMAIN
Secondary-2  status: NXDOMAIN
```

DO=1：

```text
Primary      status: SERVFAIL, flags: qr rd ra, DO=1
Secondary-1  status: SERVFAIL, flags: qr rd ra, DO=1
Secondary-2  status: SERVFAIL, flags: qr rd ra, DO=1
```

DO=0 响应的附加区包含 `global-deny.rpz.local. SOA`，因此本次 DO=0 结果可确认由全局 DENY 命中产生。DO=1 本次返回 `SERVFAIL`，且模拟上游没有记录该精确名称；但这不是公网 DNSLog 证据，也不能推翻此前隔离测试中 DO=1 完整 QNAME 外传的风险。

## DNSLog 证据边界

当前没有以下授权配置：

```text
DNSLOG_QUERY_LOG_API
DNSLOG_API_TOKEN
```

因此：

- 公网 DNSLog 基准标记为 `NOT RUN`。
- 全局 DENY 后公网 DNSLog 防外传标记为 `NOT RUN`。
- 不能把客户端 `NXDOMAIN` 或公网 DNS 解析成功本身当作 DNSLog 到达/未到达证据。

## 最终判断

该域名在隔离 DNSGuard 全局 DENY 配置下，DO=0 查询被 Primary 和两台 Secondary 返回 `NXDOMAIN`，RPZ 命中证据明确；普通客户端解析阻断验证通过。

DO=1 查询返回 `SERVFAIL`，本次精确名称未出现在模拟上游日志，但由于缺少公网 DNSLog 权威日志证据，且此前已知 DO=1 外传风险仍存在，不能宣称 DNS 隧道在所有查询模式和生产 BIND 配置下均已被完全阻断。

本次未修改 DNSGuard 功能代码、生产 BIND、生产 `named.conf`、`response-policy` 或 Zone 文件。
