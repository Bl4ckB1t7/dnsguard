# DNSGuard v1.2.0 Release Candidate（草稿）

> 本文仅为发布候选说明草稿。本轮不创建 `v1.2.0` Tag 或 GitHub Release。

DNSGuard v1.2.0 延续“控制面与 BIND 数据面分离”的架构，重点改善首次部署和 RPZ 配置接入体验。

## 主要更新

- **先启动平台，再接入 BIND**：没有 BIND、RPZ Zone 或 TSIG 时，可以先启动 Web/API，随后在 Web 向导中完成接入。
- **RPZ 初始化配置包**：生成可预览、可下载的 Primary/Secondary 配置包；应用脚本支持角色校验、备份、幂等处理、冲突拒绝和权限准备。
- **白名单导入与安全发布**：支持 TXT/JSON 导入，导入只创建 `draft`；必须人工审核、发布并确认所有 Secondary 同步。
- **Global Deny 延迟启用**：Global Deny 只能在白名单发布和同步确认后，由 BIND 管理员独立启用，再由 DNSGuard 执行只读核验。
- **Docker 部署体验**：支持可选外部 BIND Docker 网络，安装器检查实际 Subnet 是否得到明确 CIDR 授权。
- **安全提示与失败恢复**：改进 HTTPS、Bootstrap Token、TSIG、Docker 权限、配置备份和失败重试提示。

## 升级说明

- v1.0.1 已初始化部署不会自动切换到 `global` 模式；升级前应备份 JSON 状态、Secrets、TLS 和审计数据。
- `tld-deny.rpz.local` 保留为旧版兼容路径；v1.1.0+ 的全局拒绝 Zone 为 `global-deny.rpz.local`。
- 生产 BIND Primary/Secondary、TSIG、Zone Transfer 和 `response-policy` 仍由管理员独立配置。

## 安全限制

DNSGuard 不修改、reload 或 restart 生产 BIND，也不保证所有 DNSSEC 或 DNS 隧道场景都能阻止上游 QNAME 外传。客户端收到 `NXDOMAIN` 不等于完整 QNAME 未到达上游；既有隔离测试显示部分 `DO=1` 查询仍可能触发上游查询。正式上线前必须在目标 BIND 配置下独立验收。
